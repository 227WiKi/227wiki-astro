# UI 规则

新写或改动的页面和组件都按这些规则做。已经纳入静态检查的文件列在 `tests/ui-rules.test.mjs` 的 `RULED_FILES` 中，测试会检查它们；改动其他文件并完成规则检查时，把它加入这个清单。静态检查只覆盖部分源码模式；列入清单不代表继承的共享组件及最终渲染已经全面合规。
规则后面写了测试名的，由测试检查；其余规则由人在页面上检查。

## 适用范围

本项目使用 Astro、React 和 coss。UI 规则以本站既有要求、coss 组件约定、实际可读性与可访问性为依据；外部组件库的 skill 只提供参考，不自动成为本项目的验收标准。

不采用 Kumo UI 的专属风格约束：不强制全文 14px、不全面禁止 tracking 或粗字重、不禁止 hover 颜色过渡、不禁止 border 与轻微投影共存，也不要求把 coss 轮廓改成 ring。coss 风格的卡片叠加明确允许。相关差异不能仅因与 Kumo guidance 不同就列为问题。

当前审查结果见 [UI 重新审查](./ui-design-audit.md)。之前的 Kumo 截图保留为现状参考，不再作为违规清单。

## 文字

**不用大写和宽字距。** 不用 `uppercase`，字距最多 0.02em（`tracking-tight` 和默认字距都可以，`tracking-wide` 及以上不行）。作品、产品和人物的正式名称保留原文；不强制把所有英文 UI 标题改为 sentence case。这样文字读起来平稳，和正文一致。由 `tests/ui-rules.test.mjs`（"no capitals or wide letter spacing"）检查。

**字号与字重表达层级。** 正文、辅助文字、卡片标题和操作按本站字号档与 coss size 变体设置，不要求全部为 14px，也不把断点下的字号差异直接判为问题。字重按内容层级与组件约定选择，不因使用 `font-bold` 就认定违规。优先检查是否清楚可读、是否被截断、是否存在无意义的重复强调。

**标题单独成立。** 标题下面不加更小的灰色副标题，说明写进正文。这样读者只读一个标题，不用读两个。

**每个事实只说一次。** 同一屏里，同一个事实不出现在两个地方；两个数字相等时只说一个。这样一屏能放下更多事实，两份副本也不会对不上。

**用平实的话。** 页面上不出现内部用语，例如 Song ID、slug、"关联"、"曲目记录"、数据集或字段名。我们自己写的文案里不用括号补充说明，也不用 emoji 或符号当标记；字段之间不用 "·" 一类符号分隔，需要标出字段（日期、会场等）时，在字段前放一个 lucide-react 图标。这样不了解数据结构的读者也能读懂每个字。Setlist、Live、Tour 这些站内通用的名称可以用。演出名、会场名之类的数据原文照录，不受这条限制。由 `tests/ui-rules.test.mjs`（"plain words"）检查，包括不用 "·" 分隔字段。

**关联只说数据说了的事。** 一首歌和一场公演之间，只能说"已整理的 Setlist 里有这首歌"。数据里没有记录，不能说成"没有演唱过"。这样页面说的话永远不超过数据能证明的。由 `tests/ui-rules.test.mjs`（"plain words"）检查。

**来源放在参考资料里。** 来源、链接和授权说明集中放在页面的"参考资料与官方链接"部分；正文和卡片里不夹带来源说明。这样正文保持清楚，每个来源也都有出处。

**页面不展示迁移记录。** 迁移过程、字段映射、资料取舍、核实进度和授权核查记录只保留在开发文档中，禁止出现在正文、参考资料、信息框、空状态或提示里。参考资料保留正式来源链接、必要署名及面向读者的许可证信息。

## 布局

**尺寸来自设计系统。** 间距是 4px 的倍数（Tailwind 整数档，例如 `gap-1`、`p-3`；不用 `gap-1.5`、`py-2.5` 这类半档）。字号只用 12、14、16、18、20、24、30、36px，也就是 `text-xs` 到 `text-4xl`，CSS 里写对应的 rem。控件高度用 coss 的尺寸档（`buttonVariants` 的 `size`），不另写高度。coss 组件内部的默认尺寸、轮廓和交互样式按组件约定使用，不为了套用外部组件库规范而覆写；页面自定义样式按本文检查。这样各页面的控件、卡片和间距对得齐。由 `tests/ui-rules.test.mjs`（"sizes come from the design system"）检查。

**相关文字靠近，组间留出更多空间。** 标题和直接相关的内容之间，间距应小于其与下一组内容或操作的间距，例如组内 `gap-1`、组间 `gap-4`。保留本站“不在标题下加灰色小副标题”的规则。

**文字留白按内容检查。** 结合行高、点击区域和相邻内容判断留白是否合适；`p-3`、`p-5` 等等值 padding 不构成问题，不强制纵向小于横向。图片朝向外框的边距仍按下文保持相等。

**要紧凑就收间距，不缩尺寸。** 想让某部分更紧凑时，缩小间距、合并重复内容；字号和控件高度保持不变。这样文字始终好读，控件始终好按。粗指针设备上，控件的点击区域保持 coss 默认的 44px。

**收录作品卡片的字号与外观统一。** 歌曲页使用同一个 `SongReleaseCard`，采用 coss Card 的圆角、边框与轻微投影。标题为 16px、20px 行高，最多两行并预留两行；类型和发行日期与演出历史卡片保持一致，为 14px、20px 行高，字段图标为 16px。手机与桌面使用相同的字号档；有无封面保持同一文字结构与卡片高度。作品网格最多两列，每列均分并撑满可展示区域，不设固定列宽上限；四张作品卡片时排成 2×2，窄屏保持单列；不为了凑满网格重复或虚构作品。

**同一组卡片高度一致。** 一组卡片使用固定结构：标题最多两行并始终预留两行，其余每个字段一行，放不下的字段截断，完整内容放在 `title` 属性里。条目多出来的部分（例如多场公演）收进 coss Menu 这类弹出层，或者链接到详情页，不让卡片变高。这样一组卡片排列整齐，扫读时视线不必跳动。

**固定控件下不压内容，窄屏不横向滚动。** 浮动目录等固定控件不能永久挡住任何名称或控件；页面在 390px 宽时没有横向滚动。这样手机上每个名称和控件都看得到。

**吸顶区域保持层级清楚。** 可以通过留白、背景、边框或轻微投影与正文区分，不强制每个 sticky 区域都加边框。判断依据是滚动时能否分清内容、是否遮挡正文与焦点。

**键盘和动效。** 键盘焦点要看得见，并且保持控件自己的形状（例如圆角控件显示圆角焦点环，不再叠一个方框）。页面遵守 `prefers-reduced-motion`，不强制平滑滚动。这样不用鼠标、关掉动效也能使用页面。

**允许 hover 颜色过渡。** 保留 coss 与本站现有的短时颜色、边框及背景过渡；不因 `transition-colors` 就判违规。检查响应是否及时、是否出现闪烁，以及减少动态效果设置是否生效。浮层进出动画与颜色过渡分别检查。

**折叠过程中不重新挤压内容。** 退出动画完成前保留内容节点及其排版尺寸，通过外层裁剪、高度动画或 opacity/transform 隐藏，避免文字在关闭途中换行、跳动。

**弹层退出动画和焦点完整。** 按实际组件库的生命周期控制显隐，退出动画完成前不提前卸载内容，完成后可以卸载。检查 Escape、外部点击和关闭后的焦点返回，不规定所有 Dialog 永久挂载。

## 外观

**使用设计系统。** 颜色 token 定义在 `src/styles/global.css`，组件里只引用（例如 `var(--muted-foreground)`、`text-muted-foreground`），不写颜色字面量，也不在组件样式里重新定义 token。组件优先用 `src/components/ui/` 里的 coss 组件。这样细节（细线颜色、透明度）在各处一致。由 `tests/ui-rules.test.mjs`（"colours come from tokens"）检查。

**边框与轻微投影可以共存。** 允许 coss Card、Menu、Dialog 等使用 border 配合轻微投影，包括组件自己的伪元素轮廓；不强制换成 ring。仅在实际出现边线重影、轮廓变粗或层级不清时记录问题。本站对额外大阴影的限制仍适用于页面自定义样式。

**允许 coss 风格的卡片叠加。** 现有 coss `Card`、`CardFrame`、`Frame` 以及沿用其样式的媒体框架可以按设计叠加，不因嵌套或叠加本身而拆层或修改。只有实际影响阅读、操作或版面层级时才提出具体问题。

**社交媒体入口保留原设计。** 官方资料与 Instagram 使用原来的白底，X 和 TikTok 使用黑底，YouTube 使用红底，保留官方图标、按钮尺寸、悬停和提示样式。这是用户明确要求的品牌入口例外，不再按中性色或普通字段图标规则改写。

**导航栏保留毛玻璃。** 站点吸顶导航沿用半透明背景与 backdrop-blur，保留边框及亮暗主题适配。这是用户明确要求的例外，不作为装饰效果违规。

**不加额外装饰效果。** 除上文明确保留的导航与品牌入口外，不用渐变、毛玻璃、发光、大阴影，也不用品牌色铺背景。层级靠字重、字号档和间距表达。这样信息本身最显眼。由 `tests/ui-rules.test.mjs`（"no decorative effects"）检查。

**不画标志，图标只标字段。** 站点和页面用文字命名，不自制图形标志。图标只用 lucide-react，只用来标出字段，尺寸 16px（`size-4`），颜色用 `text-muted-foreground`，并设 `aria-hidden`，含义由旁边的文字表达。不用图标做装饰。这样不会有凭空设计的图形替内容说话。

**图标与文字按实际排版对齐。** 多行字段通常对齐首行，单行可用 `items-center`；按实际显示效果判断，不要求固定使用 `h-lh` 或某一种 DOM 包装。字段图标仍保持本站的 16px 档。

**自定义内外轮廓保持协调。** 图片等距边距和同心圆角按下文检查。自定义紧邻内外框时，可按实际内缩距离计算圆角；不为满足外部组件库的特定圆角档而改写 coss 基础组件。

**卡片里的图片边距相等、圆角同心。** 位于卡片中的图片，朝向外框的三周或四周必须留出相同的边距，内圆角取外圆角减去边距和边框宽度（`max(0px, 外圆角 - 边距 - 边框宽度)`），与外框圆角形成同心圆。这样图片和卡片边缘平行，转角自然对齐。

**没有图片也完整。** 很多成员、公演、作品没有海报或照片。卡片和信息框要设计成没有图片时也是完整的，不留空框。

**亮色和暗色。** 每个页面在两种主题下都可读（暗色由根元素上的 `.dark` 触发），新组件要在两种主题下都检查。站点目前还没有主题切换按钮。

**空状态要给出去处。** 列表为空时，说明现在知道什么，并给出一个能继续浏览的链接，不要停在一句"暂无"。这样读者总有下一步可走。

## 修复与验收记录

本轮项目 UI 审查中确认的导航、标题说明、自定义字号/间距、毛玻璃、社交配色、来源组织与图标问题已修复，具体变更及验证见 [UI 重新审查](./ui-design-audit.md)。

coss 默认交互样式、卡片叠加、边框与轻微投影继续保留。主题切换按钮属于独立功能改进，不因缺少按钮就认定亮暗主题不可读。Markdown 历史资料中的原文与站点作者编写的 UI 文案分别检查，不通过改写资料内容来消除 UI 规则告警。
